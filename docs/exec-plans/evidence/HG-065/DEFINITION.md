# Retained representation custody — proposed closed rule

Status: AUTHOR_DEFINITION_CANDIDATE_R2. This is a scratch specification, not installed
authority, an implementation grant, a review PASS, or an admission. The approved
direction is `inputs/custody-direction/PROPOSAL.md`; its original hash and direct
human approval are bound by INPUT_MANIFEST. R1–R4 and both complete R4 reviews are
immutable inputs. Their execution-attribution rule and actual denials remain intact.

## Purpose and semantic decisions

1. Original independently selected declarations prove custody of representations.
   They do not need to prove a historical execution occurred. Original authority
   must predate the future candidate; the selected frozen failed result may itself
   be the original declaration when protected authority independently pins it.
2. The foreign representation must arrive by an ordinary two-parent protected
   delivery. Parent order, original introduction, declaration ancestry and every
   relevant edge are part of the proof. Endpoint equality alone is insufficient.
3. A custody group contains the selected owner and exactly one foreign owner,
   one raw identity and one owner-local physical payload per owner. Every envelope
   and both payload paths count at their full actual size; no deduplication credit.
4. Custody accounting is a distinct preservation result. `acceptance_eligible` and
   `execution_reuse` are always false. Historical execution is `UNVERIFIED` in this
   result even when separately bound component facts exist. Retained original exit
   claims are claims. Unknown child exit stays null; driver exit cannot fill it.
5. Execution bodies not needed by a custody proof are opaque, byte-verified source
   objects. Native codec/classifier/source/history duties still run. Existing
   execution proofs still require their complete collection/execution/phase/JUnit
   oracles and unchanged 512-entry list cap. This explicit new purpose replaces
   the earlier execution-attribution prerequisite only for original-audit duplicate
   accounting. It neither satisfies nor short-circuits an execution reader.

## Closed entry and authority chain

Only the installed private root/host ORIGINAL audit operation described in
TRUSTED_HOST_PROJECTION.md can request this type. No public argument, caller-supplied
boolean, environment, JSON receipt, candidate module or worker verdict is a
credential. An in-process context exists only inside that installed host operation.
Before the operation constructs it, independently resolve:

- canonical repository identity and installed complete asset/controller identity;
- authenticated live protected base P, exact clean immutable candidate H and tree;
- one selected namespaced task S: final host uses the unchanged native selected-
  record rule on the live P-to-H diff; preimport uses root's already-authorized
  task ownership and the exact protected P packet, Q original record and map;
- protected packet at P and its exact task identity, original base O and frozen
  original selected result Q, including a regular mode/blob/size/hash binding;
- own already-admitted map M, its original source A and original admission C from
  the packet and original map's first-parent history; every inherited map and its
  original source/admission remains independently subject to native validation;
- exact original selected declaration at Q, and original foreign declaration F
  and delivery D from its normal protected-delivery ancestry, never a future
  candidate's assertions about itself.

Require exact 40-hex commits/OIDs, exact 64-hex content hashes, normalized literal
repository-relative paths, regular mode 100644 or 100755, and namespaced machine
identity agreement across packet/record/map. Require O ancestor P, P ancestor H
for final host execution, Q on retained selected first-parent lineage to H, map
admitted on that lineage before base import, map/source bytes unchanged and all
native retained-map/base-advance conditions. Preimport inventory instead binds
clean frozen Q as its Git-data H and checks the still-needed forward merge as
NOT_RUN; it cannot claim final P ancestor H or final eligibility.

Original declaration kinds are closed to the native task result or governance
record selected by the protected packet. Resolve its schema from original
authority and exact member pointers under native `files_changed[*]`,
`checks_run[*].evidence_ref` and (where that native schema defines it)
`evidence_refs[*]`; record the pointer(s) actually used. A files_changed declaration
is custody membership only and can never substitute for a check/output ref.
Match the namespaced
owner, immutable declaration revision/path/blob/bytes and exact ref membership.
For a declaration's revision/path tuple, require one exact object binding across
every member. Independently read the original bytes, verify mode/OID/size/hash and
original native schema, and resolve each pointer to that exact ref. Pointer syntax,
an arbitrary ordinal, a matching basename or a declaration claim is insufficient.
No recursion through arbitrary body strings, basename inference or new declaration
file is allowed. Multiple pointers to the same ref in one original record are
ordinary references; conflicting record/owner/revision claims deny. Original FAIL,
BLOCKED or SPEC_CHANGE_REQUIRED is valid custody input and retains that status.

Unmapped ordinary envelopes are permitted only as unchanged ordinary retained
representations in an already-authenticated retained-map original-audit context.
Map context is not a claim that the six envelopes are map entries. A mapped
representation must also satisfy its own exact original/replacement snapshot,
source, execution-field preservation and admission proofs; neither form exempts
any own or inherited map from the full native audit. New/late maps cannot establish
custody. No map, declaration or historical object is modified by this rule.

The O-to-Q original preservation diff also contains the normally imported foreign
record. It is not a ci-pr one-record selection input. Preimport does not pretend
that native final P-to-H selection or final ancestry has run on that diff, nor
infer task authority from a public S parameter. Its private root-selected packet
must independently agree with original Q identity and map owner. Final native
live-base selection and every selected/prerequisite guard still run unchanged.

## Complete group and representation predicate

Enumerate the full native O-to-H changed evidence inventory first, without filters
that discard errors, foreign paths, arbitrary suffixes or map paths. Resolve all
ordinary envelope payloads under native codec/classifier rules. For each raw hash
with raw size at least 16384, enumerate every reference and physical payload in
the complete inventory; exact raw-byte equality is mandatory in addition to hashes.
Only a complete group with exactly two owners, S and one independently delivered
foreign owner, is eligible for custody consideration. An additional owner, plain
bulk copy, unreferenced payload, extra alias, absent ref, inconsistent raw identity,
multiple physical payloads in one owner, conflicting original declaration, changed
foreign bytes, move/reencoding or ambiguous group denies the whole group.

Each envelope must independently pass unchanged native envelope fields, sizes,
owner-local same-directory content-addressed payload name, tested-commit existence
and ancestry, stored/raw integrity, codec EOF/trailing-data/nested-envelope and
classifier checks. Metadata claims do not imply execution proof. Same-owner
envelopes can reference their one same-directory payload under existing storage
rules; distinct execution claims remain distinct. Globally disjoint physical paths
are counted exactly once per actual file, never once per raw hash. Deduplicate only
multiple references to the identical physical payload. Total changed bytes/files
must equal native actual inventory, including any paths outside these groups.

Foreign D has exactly two parents: previously protected first parent B and normally
reviewed PR head second parent J. F is ancestor J; D is ancestor P and H. Prove
the foreign group's exact bytes at F, J, D, P and H, absence at B where newly
introduced, and no independent introduction on selected lineage before D. Verify
every parent edge from original foreign introduction through J/D/P/H, including
side branches and incoming boundaries. Permit only the first declared introduction
of an absent path to its exact original regular blob, the authenticated normal
foreign delivery D, and a retained selected two-parent forward import of D.
For either import the first parent's path must be absent, the second parent's path
must be exact original, and the second parent must be D or descend from D (at D,
it is the verified foreign PR head J instead). All actual parent edges are checked;
this permits delivery of the original copy, never a single-parent reintroduction.
After introduction any
deletion, restoration, byte/mode change, rename or incompatible boundary denies.

Selected introductions must be on retained selected task lineage. They are absent
from protected P; exact original introduction parent(s) prove absence and no
preexisting alias. Every relevant parent edge from introduction to Q/H preserves
the exact original mode/blob/bytes, including transient reverted changes and
incoming side branches. Native complete original storage/history/map audit still
covers the broader O-to-H lineage; this predicate adds no cutoff to it.

Bind each envelope history's path and original object to that exact member envelope,
and each payload history to the exact owner-local payload object. Shared physical
paths must have identical introduction and history; repeated commit IDs must have
identical ordered parent metadata across all histories. Every interval is acyclic,
has a connected introduction-to-required-endpoint path, and contains only relevant
ancestors of the required endpoints plus its explicit incoming boundary parents.
Disconnected components, extra cycles, absent endpoints and contradictory original
bindings deny. Boundary parents have absent path states; no dangling boundary is
allowed. Required endpoints are Q for selected paths and both P/Q for foreign paths.
Foreign F/J/D are exact original nodes on those intervals: F ancestor J, D's ordered
parents and import equal B/J, and D ancestor P/Q. Every later selected import's
second parent must descend from the same D. Relation labels alone cannot establish
those relations. Source-object authentication remains the independent installed
reader's duty; synthetic model inputs never construct that authority.

## Opaque body boundary

Custody parses only original authority/declaration/map schemas, envelope metadata,
Git object metadata and group/edge inventory. The collection raw bytes and any
ancillary producer command, observer, JUnit or index bytes are retained source
objects. Integrity/codec/classifier checks that native readers require run in full.
Custody does not invoke the old execution-parent partition or count its phase
reports. It must not rewrite them or truncate a list to fit a bound. A future use
of those bodies for execution attribution must invoke the original required full
oracles with the unchanged cap and accept their denial. Source role inspection,
original-source lineage, raw execution output and custody byte cache are distinct.

Concrete retained interruption: original6358 driver143 and unknown unit child exit
remain separate. No envelope exit0, shared collection bytes, representation count,
command spelling or timestamp resolves that unknown. The c4b explicit observer
mapping gap remains recorded. Three 741-report bodies still deny the earlier
512-list execution-attribution partition. No historical PASS is reissued.

The original authority/declaration reader preserves each exact native schema and
its existing source-list rules. Original sources have complete byte, token, node
and depth bounds; projected custody member/pointer/history proof lists retain the
512-entry cap. An original native files_changed list is neither an execution phase
list nor a projected proof list. The actual selected original record has562 entries
there, and its exact original native schema has no maxItems. Read that source fully
and resolve exact pointers; no first512 truncation, cap increase, execution-body
recast or native schema change is permitted. Original schema validation and source
bounds remain conjunctive. The selected declaration's base_commit is its then-live
base D, distinct from audit O; original Q/O authority comes from protected packet/
map bindings, never an invented equality of those different bases.

## Output and atomic rejection

OUTPUT_SCHEMA.json closes diagnostic runtime output. Every field is required;
unknown fields and bool-as-int values reject. Runtime status is only
`CUSTODY_ACCOUNTED_ORIGINAL_INVENTORY`, `CUSTODY_DENIED`, or
`CUSTODY_UNPERFORMED`. Author study status is separately
`CUSTODY_PREDICATE_DEMONSTRATED` and never a runtime result. A custody result is
not `ACCOUNTED_PROTECTED_IMPORT`, REVIEW_SOURCE_LINEAGE, REVIEW_RECORD_ONLY,
execution attestation, task/review/storage/global/requirement PASS or admission.

An accounted runtime result requires the complete conjunction of authenticated
entry, all custody predicates, native original audit's every independent guard
and strict actual live-base audit; all remaining release/merge gates remain
required separately. `complete` can be true only with all work completed within
bounds. Any incomplete context/group, unknown/conflicting provenance, limit or
deadline exhaustion invalidates the entire invocation: zero accounted paths and
bytes, every group denied, no positive cached verdict, complete false. A completed
ordinary denial may have complete true but still accounts nothing. Preserve actual
diagnostics and actual processed counts; do not clamp observed work/time to caps.
Native audit errors other than the exact proven duplicate group remain errors.
Native changed-file totals always include all physical copies regardless of result.
Every complete output, including an ordinary completed denial, independently checks
every actual counter and elapsed nanosecond value against the inclusive bounds.
A non-exhaustion reason cannot hide an actual overrun. Actual overruns require
complete=false, CUSTODY_DENIED, zero accounting, no surviving groups and the proper
exhaustion reasons; actual exceeded values remain. Recheck the shared context after
each predicate (also on denial), before finalization and against the final observed
clock/counters before publication. Both counter and deadline overruns retain both
reasons. CUSTODY_UNPERFORMED has exactly [UNPERFORMED], incomplete status, zero
accounting and NOT_RUN native/live guards; any actual exhaustion is instead denied.

## Bounds, caches and remaining gates

BUDGETS.json gives inclusive upper bounds and charging units. Check capacity
before allocating/reading/decoding and again after actual work. A worklist reserves
processed + already-pending + incoming children before allocation. Large opaque
body lists are not custody structural proof inputs; native body checks retain
their own caps. Full native map/history/storage checks are charged under the same
finite context; no separately reset cache/child allowance can multiply a limit.
Every immutable read/Git operation and actual output byte is charged, even a
rejected one. A timeout or incomplete command invalidates the whole context.

Byte-cache key: repository/object-format/commit/path/mode/blob/bytes/sha256/purpose.
Verdict key additionally binds installed authority/asset identity, S/O/P/Q/H,
packet/map/source/admission/declaration/delivery identities, full group inventory
digest, every graph edge digest, invocation ID and proof purpose. Byte equality
does not allow cross-purpose verdict reuse. Invocation IDs are nonempty ASCII
1–128 bytes, minted by host. Entries never survive invocations; immutable bytes may
be reread under a new budget but stale proof is not promoted. Capacity exhaustion
fails closed, rather than accepting a cache miss or clearing errors. No cache is
shared with execution/review/RRO/M3/source/admission. Every invocation's final
result is committed atomically only after all groups finish, or fully discarded.

CALLER_MATRIX.json and TRUSTED_HOST_PROJECTION.md preserve mandatory separate
live-base, selected freshness/full suffix/RRO, prerequisite/result/review, source,

normal merge. Missing native/live work is NOT_RUN, not implicitly successful.
