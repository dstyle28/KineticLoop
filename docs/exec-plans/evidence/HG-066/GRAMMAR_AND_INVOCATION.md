# Closed grammar, actual observations and invocation projection

This candidate defines one phase sequence in PHASE_MATRIX, one new non-final
PREIMPORT_SCHEMA, and one strict public-regression result in PUBLIC_DENIAL_SCHEMA.
Sequence events use exact phase names/actors and exact per-phase keys; extras and
missing/reordered events reject. SEQUENCE_SCHEMA expresses shape; independent
native observations, original-source/graph crossbindings and operational authority
remain necessary. Neither model events nor their schemas are production inputs.

Non-final positive grammar is PREIMPORT_PRESERVATION_OBSERVED / complete true /
actual host integer0 / exact S,O,P,Q,K,tree,installed K,controller,authority,
invocation / complete native inventory, every map and every ancestral/incoming edge /
all unchanged custody predicates / exact preserved physical dispositions / no
unaccounted errors. Live, selected-final, admission and App are exactly NOT_RUN;
historical execution UNVERIFIED, acceptance/reuse false. Non-final denial has
zero dispositions and ready=false, complete false on any incomplete/exhausted
work. A completed ordinary denial has actual nonzero host exit. Unknown/interrupted
host exit is null, complete false and explicit INCOMPLETE_CONTEXT/INTERRUPTED;
known driver exit is distinct. UNPERFORMED has exact reason and no completed work.
Every complete status respects all22 counters and elapsed120s; excess values remain.

Native diagnostic grammar is one normalized literal `path:duplicate-bulk:prior`
per actual native occurrence, canonical set order, with each endpoint<=1024 chars;
2064 is a narrower derived representation bound, not a new source/path budget.
The public enclosing oracle compares complete native shape and all physical
inventory facts/bytes plus this exact independently derived diagnostic set. It
never consumes the private PREIMPORT/final output schema, a custody receipt or
status marker. Its ordinary child still exits nonzero. Model child observations
are explicitly synthetic; real project O-to-K/native runtime is NOT_RUN here.

The future PRIVATE invocation is a direct root-operator call to the exact
independently reviewed installed local_gate function, in isolated `python -I`.
The four selector/location operands are: existing private config location,
root-owned immutable Git-data store location, root's already-authorized namespaced
task selector, fresh root-owned destination. They supply no trusted classes,
booleans, P/O/Q/K, expected hashes, authority JSON, execution receipt or verdict.
Only existing private configuration/key possession plus fresh authenticated App
repository/P read, complete installed ASSETS checks, installation-wide lock,
protected packet/root task ownership corroboration and clean owned Git store
establish operational authority. A public compact/check-harness/worker argument
cannot enter this invocation. No new config or admission field is introduced.

Installed imports use ONLY the reviewed absolute versioned release. Candidate
Git objects are inert data. A future implementation must keep the authorized
original-operation continuation lexical/private inside the freshly authenticated
installed host; no public `TrustedContext`, factory, JSON deserializer, fixture
class or trust flag can construct it. Byte/proof primitives called directly by
untrusted code supply data/diagnostics only, never an installed operation result.
Even possession of a well-shaped private observation is not invocation authority.
`installed()`/App authentication/lock/owned store/native reads and before/after
snapshots are real operations, not caller booleans. Root observes and verifies
them directly; serialized receipts remain evidence outside Git and cannot be
imported as a reusable readiness credential.

All data authority at staging is exact protected P, independently Git-bound;
K's added source code is complete reviewed installed code, not an original record
or evidence declaration. Ordinary HG059 review/source callers still load their
own exact native validation-revision schema/declarations. This private staging

Changing code/installed assets needs a new exact installation review before any
renewed private proof. No Q-only proof, cheaper prefix, post-import deferral or

implementation records actual native trace completion; a flag or expected digest
supplied by the caller is never accepted. These diagnostic fields add no CLI
option, custody dispatch, global schema/admission field or trust permission.
Original historical CLI outputs remain unchanged at their original revisions.
No old output is recast into the new diagnostic shape.
