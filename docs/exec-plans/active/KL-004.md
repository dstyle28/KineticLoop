## Deliverables
- A closed error-code enum whose wire values preserve every command rejection code named
  by frozen DB §3 and §11 exactly. Do not normalize, alias, or collapse
  `IDEMPOTENCY_KEY_REUSE_WITH_DIFFERENT_PAYLOAD` and the command-specific
  `IDEMPOTENCY_CONFLICT` spelling.
- Immutable receipt identity/result base models for the frozen S02 fields, using the
  merged KL-003 canonical ID, hash, JSON and UTC-time primitives. The base contract may
  carry the frozen `status` field but MUST NOT invent a closed receipt lifecycle that the
  frozen authorities do not define.
- A pure replay/mismatch decision boundary suitable for later CommandGateway persistence:
  the same receipt identity and request hash returns the original result identity with
  `replayed=true`; the same identity with a different request hash cannot replace the stored
  result and rejects with the command-bound frozen error identity. Commands governed only by
  DB §3 use `IDEMPOTENCY_KEY_REUSE_WITH_DIFFERENT_PAYLOAD`; the DB §11
  BeginBuild/WriteCandidate and RevokeArtifact bindings use `IDEMPOTENCY_CONFLICT`. The base
  decision boundary MUST require or derive the command binding rather than hard-code one
  mismatch code for every command.

## Definition of Done
Focused unit tests prove exact error-code wire identity, strict receipt identity and field
validation, original-result replay for the same key/hash, exact generic mismatch rejection
and exact §11 command-specific mismatch rejection for the same key/different hash, and
rejection of structurally ambiguous or behavior-overrideable wire input.
No receipt field, model text, confidence, reasoning, or citation is treated as
admission/approval/authorization or as permission to execute a command.

  `.venv/bin/pytest -q tests/unit/contracts/test_receipts.py -k same_key_different_hash_rejected`
